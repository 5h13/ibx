  - `app_role` enum gains `business_admin` (Business Super Admin tier) — additive, not yet consumed by any policy or app-layer permission check; that wiring is deferred, explicitly, to the admin-UI phase.

  - `public.current_business_id()` helper (security definer, mirrors the existing `is_super_admin()`/`in_section()` pattern in `schema.sql`).
  - `business_id` added as a **RESTRICTIVE** RLS policy layer — not a replacement — across **88 business-scoped tables**, derived directly from every `create table` in the migration set (101 tables total). The 13 tables left global are exactly the locked shared-master set: `finance_suppliers` + its contacts/documents, `finance_procurement_items` (Product Master), `finance_procurement_item_suppliers`, `finance_catalog_categories`, `finance_catalog_units`, plus lookup/category tables (`admin_policy_categories`, `asset_categories`, `employee_document_types`, `leave_types`, `supply_categories`, `workflow_registry`).   - Every business-scoped table also gets a `default <ISHABELLA id>` on `business_id` as a transitional safety net, since no app write path sets it explicitly yet. **This default must be removed once the app layer is updated to set `business_id` explicitly from the acting user's session** — until then it silently assigns new rows to Ishabella regardless of who's writing, which is only correct while there is a single business.
